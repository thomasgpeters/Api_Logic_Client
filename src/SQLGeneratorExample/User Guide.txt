# The SQL Generator for FutureBasic
**Use a SQL database from FutureBasic without writing SQL.** You describe each statement with Cocoa dictionaries and arrays - the tables, the columns, how tables join, the filters, the order - and the SQL Generator writes the SQL for you, with every value kept apart from it in `?` placeholders. The same dictionaries you build for a query are the rows you get back, so data goes in and comes out in one shape. This window explains the model, then every function, one by one.

![SQL Generator Diagram]
The object model: a statement is a dictionary of arrays, each entry a small dictionary. **View Diagram** shows it full size.

## How it fits together
A SELECT is a dictionary (InitQueryDictionary) with arrays inside it: the tables, the columns, the joins, the filters and the sort order. Each Add... function adds one dictionary to one array. GenerateSelectSQL reads the arrays and writes the SQL; QueryParameterValues lists the values for its `?` placeholders, in order. INSERT, UPDATE and DELETE are a dictionary each, with the same filter entries. A runner (SQL Generator SQLite.incl here) sends the SQL and the values to the database and gives rows back as dictionaries.

# The functions, one by one

## Describing a SELECT
**fn InitQueryDictionary** - a new, empty query; every SELECT starts here.
```
query = fn InitQueryDictionary
```
**fn AddTableToQuery( query, tableName, aliasName )** - a table to read from, and the short name (alias) the other functions use for it.
```
fn AddTableToQuery( query, @"person", @"p" )
```
**fn AddColumnToQuery( query, columnName, aliasName )** - a column to return, as alias.column, and its name in the result rows.
```
fn AddColumnToQuery( query, @"p.surName", @"Surname" )
```
**fn AddAssociationToQuery( query, leftAlias, leftColumn, rightAlias, rightColumn, operator )** - how two tables join (`_isEqual` for a join).
```
fn AddAssociationToQuery( query, @"a", @"personID", @"p", @"id", _isEqual )
```
**fn AddFilterToQuery( query, alias, column, value, type, 0, operator, logic )** - one condition of the WHERE clause. The value goes to a `?` placeholder, never into the SQL. `logic` joins it to the one before: `_and` (or 0) or `_or`.
```
fn AddFilterToQuery( query, @"p", @"balance", fn NumberWithDouble( 100.0 ), _realType, 0, _isGreaterThan, 0 )
```
- **operator**: `_isEqual`, `_isNotEqual`, `_isLessThan`, `_isGreaterThan`, `_isLessThanOrEqual`, `_isGreaterThanOrEqual`, `_isLike`, `_isNotLike`, `_isNull`, `_isNotNull` (the last two take no value: pass NULL)
- **type**: `_textType`, `_integerType`, `_realType`, `_blobType`, `_nullType`

**fn AddOrderToQuery( query, alias, column, descending )** - one column of the ORDER BY, most important first; YES sorts it descending.
```
fn AddOrderToQuery( query, @"p", @"surName", NO )
```
**fn GenerateSelectSQL( query )** - the SELECT statement the query describes.
```
sql = fn GenerateSelectSQL( query )
// SELECT "p"."surName" AS "Surname" FROM "person" AS "p" WHERE "p"."balance" > ? ORDER BY "p"."surName"
```

## Adding a row: INSERT
**fn InitInsertIntoDictionary** - a new, empty INSERT.
**fn AddTableToInsert( statement, tableName )** - the table the row goes into.
**fn AddColumnToInsert( statement, columnName, value, type )** - one column and its value (NULL for SQL NULL).
**fn GenerateInsertIntoSQL( statement )** - the INSERT statement, or NULL when the table or the columns are missing.
```
statement = fn InitInsertIntoDictionary
fn AddTableToInsert( statement, @"person" )
fn AddColumnToInsert( statement, @"surName", @"Lima", _textType )
sql = fn GenerateInsertIntoSQL( statement )
// INSERT INTO "person" ( "surName" ) VALUES ( ? )
```

## Adding many rows at once
The opposite of a SELECT: an array of dictionaries, column to value, goes in as one INSERT.
**fn InitInsertRowsDictionary** - a new, empty multi-row INSERT.
**fn AddRowsToInsert( statement, rows )** - the rows (an array of dictionaries); their keys become the columns, sorted. A column a row has no value for goes in as NULL.
**fn SetInsertColumns( statement, columnNames )** - the columns and their order yourself, instead of the rows' keys.
**fn GenerateInsertRowsSQL( statement )** - one INSERT with a ( ?, ? ) group per row.
```
statement = fn InitInsertRowsDictionary
fn AddTableToInsert( statement, @"person" )
fn AddRowsToInsert( statement, rows )
sql = fn GenerateInsertRowsSQL( statement )
```
For thousands of rows, insert a few hundred at a time inside one transaction.

## Changing rows: UPDATE
**fn InitUpdateDictionary** - a new, empty UPDATE.
**fn AddTableToUpdate( statement, tableName )** - the table.
**fn AddColumnToUpdate( statement, columnName, value, type )** - one column and its new value.
**fn GenerateUpdateSQL( statement )** - the UPDATE statement. It needs at least one filter (AddFilterToQuery, with an empty alias `@""`); without one it returns NULL, so it can never change a whole table by accident.
```
statement = fn InitUpdateDictionary
fn AddTableToUpdate( statement, @"person" )
fn AddColumnToUpdate( statement, @"balance", fn NumberWithDouble( 99.95 ), _realType )
fn AddFilterToQuery( statement, @"", @"surName", @"Okafor", _textType, 0, _isEqual, 0 )
sql = fn GenerateUpdateSQL( statement )
```

## Removing rows: DELETE
**fn InitDeleteFromDictionary** - a new, empty DELETE.
**fn AddTableToDelete( statement, tableName )** - the table.
**fn GenerateDeleteFromSQL( statement )** - the DELETE statement; like UPDATE, NULL without a filter.
```
statement = fn InitDeleteFromDictionary
fn AddTableToDelete( statement, @"contact" )
fn AddFilterToQuery( statement, @"", @"id", fn NumberWithInteger( 8 ), _integerType, 0, _isEqual, 0 )
sql = fn GenerateDeleteFromSQL( statement )
```

## The values and the names
**fn QueryParameterValues( statement )** - the values for the `?` placeholders of any statement above, in placeholder order: the column values, then the rows of a multi-row INSERT, then the filters.
**fn QueryNull** - SQL NULL as a value (a Cocoa array or dictionary cannot hold NULL itself).
**fn QuoteSQLName( name )** - a table or column name quoted for SQL: `Order` becomes `"Order"`, `a.id` becomes `"a"."id"`. The generator does this for every name; a name already quoted is kept.

## Running it on SQLite (SQL Generator SQLite.incl)
The generator only writes SQL; this file is one way to run it. Use your own SQLite code instead if you have some.
**fn SQLGenOpen( path, create, @db )** - open a database file (":memory:" for one in memory); YES creates it when missing. Returns `_sqlGenOK` when it opened.
**fn SQLGenExecute( db, sql, values, rows )** - run one statement with its values; when `rows` is a mutable array, each result row is added to it as a dictionary (column name or alias to value). Returns `_sqlGenDONE` when it ran.
**fn SQLGenChanges( db )** - the rows the last INSERT, UPDATE or DELETE changed.
**fn SQLGenLastInsertID( db )** - the id of the last row inserted.
**fn SQLGenErrorMessage( db )** - SQLite's message for the last error.
**fn SQLGenClose( db )** - close the database.
```
ptr db
rows = fn MutableArrayNew
fn SQLGenOpen( @"/path/to/crm.sqlite", YES, @db )
fn SQLGenExecute( db, sql, fn QueryParameterValues( query ), rows )
for row in rows
  NSLog( @"%@", fn DictionaryObjectForKey( row, @"Surname" ) )
next
fn SQLGenClose( db )
```
Values come back as Cocoa objects: INTEGER and REAL as NSNumber, TEXT as NSString, BLOB as NSData, NULL as NSNull. The step-by-step calls under SQLGenExecute (SQLGenPrepare, SQLGenBind, SQLGenStep, SQLGenColumnValue, SQLGenFinalize) are there for your own loops.

# Using the SQL Generator in your own app
Everything below is done in the FutureBasic editor and the Finder - no other tool is needed. The SQL Generator is four FutureBasic source files: copy them, drag them into your project, link SQLite, and call the functions.

## 1. Copy the four files
From this folder (or the download), copy these files into your own project's folder, next to your other source files:
```
DataObject.glbl            the constants: operators, AND / OR, value types
DataObject_Super.incl      the builders: describe a statement
DataObject.incl            the SQL: GenerateSelectSQL and the others, QueryParameterValues
SQL Generator SQLite.incl  runs the SQL on SQLite (leave it out if you have your own SQLite code)
```

## 2. Drag them into your project
- Open your project in the FutureBasic editor, so its **project window** - the list of its files - is on screen.
- Select the four files in the Finder and **drag them into the project window**.
- Put them in this order, **above your own files**: FutureBasic builds a project from the top of the list to the bottom, and a function has to be defined before anything uses it. Drag a file up or down in the list to move it.
```
DataObject.glbl            (with your other .glbl files, near the top)
DataObject_Super.incl
DataObject.incl
SQL Generator SQLite.incl
... your own files ...
```
The example's own project, **SQLGeneratorExample.fbeproj**, is set up this way: open it and look at its project window.

## 3. Link SQLite
Open **Build Settings** and add this to **Compiler options**:
```
-lsqlite3 -Wno-unused-command-line-argument
```
The first links the SQLite library that comes with macOS. The second stops clang from saying "-lsqlite3: linker input unused" once for every file (FutureBasic passes the compiler options to every compile). Only the SQLite runner needs it.

## Or: a single-file program
A program that is one .fb file, not a project, includes the files at its top and sets the option with #build (which works in single files only). Keep the four files in the same folder as the .fb file:
```
include "DataObject.glbl"
include "DataObject_Super.incl"
include "DataObject.incl"
include "SQL Generator SQLite.incl"
#build CompilerOptions @"-lsqlite3 -Wno-unused-command-line-argument"
```
**SQL Generator - Smallest Program.fb** in this folder is exactly that, in about 60 lines: open it in FutureBasic and run it - it makes a table, adds three people with one INSERT, and reads back the ones with a balance over 100.

## 4. Open your database and make its tables
```
ptr db
fn SQLGenOpen( @"/Users/you/Library/Application Support/My App/my.sqlite", YES, @db )   // YES: create the file
fn SQLGenExecute( db, @"CREATE TABLE IF NOT EXISTS person ( id INTEGER PRIMARY KEY, surName TEXT, balance REAL )", NULL, NULL )
```
A new database file is empty: create its tables with plain SQL first (CREATE TABLE IF NOT EXISTS is harmless when they exist). Build the path from the Application Support folder rather than typing it.

## 5. Describe, generate, run
```
query = fn InitQueryDictionary
fn AddTableToQuery( query, @"person", @"p" )
fn AddColumnToQuery( query, @"p.surName", @"Surname" )
fn AddFilterToQuery( query, @"p", @"balance", fn NumberWithDouble( 100.0 ), _realType, 0, _isGreaterThan, 0 )
rows = fn MutableArrayNew
fn SQLGenExecute( db, fn GenerateSelectSQL( query ), fn QueryParameterValues( query ), rows )
```
Every function is explained above, one by one.

## Good to know
- **Names it uses.** Functions starting Init..., Add..., Generate..., Query..., QuoteSQLName and SQLGen...; constants `_isEqual` to `_isNotLike`, `_and`, `_or`, `_nullType` to `_blobType`, `_sqlGenOK`, `_sqlGenROW`, `_sqlGenDONE`. Give your own functions and constants other names.
- **Your own SQLite code instead.** Leave out SQL Generator SQLite.incl and the compiler options; prepare the SQL, then bind the values of `fn QueryParameterValues( statement )` to its `?` placeholders, in order, starting at 1.
- **A newer version.** Copy the four files again over the old ones; nothing else changes.
- **Errors.** When SQLGenExecute returns something other than `_sqlGenDONE`, `fn SQLGenErrorMessage( db )` says why; the SQL and the message are also logged.

# What it does for you
- **Parameterized.** Values never go into the SQL text: they are bound to `?` placeholders. No SQL injection, no quoting of names like O'Brien.
- **Names quoted.** Tables and columns are quoted, so names like `Order` or `Group`, or with spaces, just work.
- **Safe by default.** An UPDATE or DELETE without a filter returns NULL instead of SQL (example 9).
- **SQLite types kept.** Numbers come back as numbers, text as text, NULL as NSNull.
- **Good to know.** IN writes a single `?`, so it matches one value: use OR filters for a few values. The generator writes queries, not schemas: create your tables with plain SQL (CRM Database.incl).

# This example
The window opens with all ten examples run, in one scrolling output: for each, the FutureBasic that builds its dictionaries, then the SQL, the values and what came back. **Run All** (Return or Command-R) runs them again; the **Examples** menu runs one at a time (Command-1 to Command-0); **Clear** (Command-K) empties the output; **Reset Database** makes the database again (examples 6, 7, 8 and 10 change it); **Examples > Log to NSLog** writes the output, and the SQL Generator's own messages, to the NSLog window too (isLoggingOn, NO by default: every NSLog is gated on it).
The database is `~/Library/Application Support/SQL Generator Example/crm.sqlite`, made on first launch:
```
person   id, type, givenName, middleName, surName, balance
address  id, personID -> person.id, type, street, apartment, city, state, zip
contact  id, personID -> person.id, type, contact
```
The five people in it are made up. Even its sample rows go in through the generator's INSERT builder.
