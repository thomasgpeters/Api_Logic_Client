App Builder for FutureBasic

Executive summary, 24–26 November 2026, and what comes next  ·  Imagery Business Systems, LLC

The headline. The FutureBasic product has its name: App Builder for FutureBasic, built as Studio for FB. The Studio and the SQL Generator example compile and run on the Mac. The Lite edition gained a Form designer, Mac-style pill buttons, record popovers and coded value lists; the Enterprise edition has started - the Studio reads any API Logic Server project's model; and the SQL Generator is nearly ready to share with the FB list. About 90 commits in Api_Logic_Client, 3 in Test_Xib_View.

What landed

Studio for FB (the app builder)

  • Form designer: 1–3 column forms, Hidden fields, read-only keys; date, time and date-and-time pickers; Dropdowns from a related table or a typed list; radio buttons, checkboxes; value lists with codes (R = Retail stores R, shows Retail)
  • Usability: menus regrouped, keyboard shortcuts, a working toolbar, commands enabled only when they apply, a clickable crumb trail, app and entity icons
  • Open an API Logic Server project from its folder, model file, a public GitHub repository, or by drag and drop; models.py read as text, checked against SQLAlchemy
  • Renamed: src/AppBuilder, Studio for FB.fbeproj; the old Application Support folder moves over on first launch

Generated apps

  • Mac-style pill buttons (Save in the accent colour, Delete in red), with a theme switch
  • An info button beside every related-record Dropdown: the related record's details in a popover (Order → Customer, Employee → Department)
  • Navigation from the top, a Business Objects heading, the app name large beside its icon

Behind the scenes

  • API Logic Server's behaviour measured against a running server (25 checks)
  • The linter catches three more build-breaking mistakes
  • Docs and backlog fully up to date and prioritized

SQL Generator (open source, MIT, for the FB list)

  • Module: joins fixed, ORDER BY, INSERT of many rows from an array of dictionaries; an uninitialized-variable bug fixed in all three copies
  • Example app: one scrolling output with all ten examples run at launch; the window titled "SQL Generator Example by Imagery Business Systems, LLC"
  • Help window: the object model diagram, then every function explained one by one; Open in Preview, Export (PDF or Rich Text), View Diagram
  • Using it in your own app: step-by-step drag-and-drop instructions for the plain FB editor, plus a 60-line single-file program to try first
  • A JSON:API version of the same dictionaries for Enterprise, tested against a live server - the same rows either way

Decisions made

  • Names: App Builder for FutureBasic (without "Imagery"); the built app is Studio for FB; Imagery LogicBank Studio remains the separate C++ product
  • The model belongs to API Logic Server: Lite reads the SQLite file, Enterprise reads the ALS project
  • Maps: Apple's MapKit; the Map view is designed for any set of rows with latitude and longitude, and backlogged

What's next: the top five

  1. Build a whole app with Studio for FB, end to end. Merge, build the Studio, generate the Northwind app and build it. Nothing proves the Lite edition until a generated app runs. The same build fixes the Form layout bug and checks the newest features.
  2. Publish the SQL Generator. Create the GitHub Pages repository; the site and the download get built; post to the FB list. Little cost, and the first thing the FB community will see.
  3. Finish the Modern look for generated apps. Toggle switch, combo box, date and time display, calendar picker, colour picker - small and alike - then the Map view, starting with the MapKit test on the Mac.
  4. Enterprise data. The data layer that reads and saves through API Logic Server, with sign-in: an ALS project becomes a working three-tier app. The groundwork is done.
  5. Business rules in FutureBasic. Port the rules import / export to FB, then build the Rules page in the Studio. LogicBank for FutureBasic is what sets these apps apart.

After those: a Lite release (tagged, with a download on the site), the generated app's toolbar, multi-window layouts, users and roles, and the Studio's context menus.
